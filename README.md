# agent-envelope-example

Runnable examples for `agent-envelope-sdk` and the hosted AgentEnvelope governance layer.

AgentEnvelope is not only an AI-agent demo. In this repo, an "agent" is any bounded action identity: a named actor, operation, resources, decay policy, and verifiable address. That actor can be a chatbot, backend worker, workflow step, hotel key, device command, drone dispatch, robot instruction, or any other system trusted to act.

Each example folder has a small README with the abstract, command, and expected result. Start with [examples/README.md](./examples/README.md).

- `.env.local`
- `mint-delegate.json`
- `hosted-records.json`
- `signed-payload.json`

These are intentionally ignored by git.

## Layers

| Layer | What it proves | Commands |
|---|---|---|
| Sovereign offline | Root to domain to action capability to local signature verification | `npm run sovereign`, `npm run use:cases`, `npm run vault:delegate` |
| Hosted governance | Portal-issued delegate, API-keyed mint/verify, receipts, records, legitimacy | `npm run portal:setup`, `npm run bot`, `npm run verifier`, `npm run hosted:multi` |
| LLM/workflow demos | Model intent constrained by delegated authority | `npm run llm:drift`, `npm run multi:agent`, `npm run hosted:escalation`, `npm run hosted:overreach` |

## Setup

```bash
npm install
cp .env.example .env.local
```

Offline examples work immediately:

```bash
npm run sovereign
npm run use:cases
npm test
```

Hosted examples require portal values in `.env.local`:

| Variable | Source |
|---|---|
| `AE_API_KEY` | Account API key from the web app |
| `AE_OWNER_USER_ID` | Vault page `User id`; used as hosted record owner override |
| `AE_BOT_ID` | Stable local bot label, for example `support-agent` |
| `AE_BOT_KEY` | Local bot identity private key generated by `npm run portal:setup`; not a portal output and not the vault root |
| `AE_DELEGATE_ID` | Active delegate id from the web app |
| `AE_MINT_MATERIAL` | One-time mint material from delegate issue |
| `AE_LEGITIMACY_ID` | Hosted legitimacy id attached to the active delegate |

Run the setup check:

```bash
npm run portal:setup
npm run preflight
```

For the full portal walkthrough, see [examples/04-portal-hosted-bot](./examples/04-portal-hosted-bot/README.md).

`npm run mcp` starts a server and is therefore not part of `test:all`.

## Current Hosted Showcase

The most complete product demo is:

```bash
npm run hosted:multi
```

It proves:

- delegate fetch from hosted governance
- hosted mint verification
- local derivation and signing without sending signing material to the API
- autonomous delegated public record publication
- hosted verification against published records
- legitimacy ref propagation when the delegate has a hosted legitimacy state

The generated verifier-safe records are written to `hosted-records.json`.
